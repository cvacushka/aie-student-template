## 2. Protocol

Опишите ваш "честный" unsupervised-протокол.

- Препроцессинг: Для всех датасетов применено масштабирование признаков с помощью `StandardScaler` (scaling). Проверка пропусков выполнена для всех датасетов - пропусков не обнаружено, поэтому `SimpleImputer` (imputation) не применялся. Все выбранные датасеты (01, 02, 03) содержат только числовые признаки, категориальных нет, поэтому `OneHotEncoder` (encoding) не применялся. PCA использовался только для визуализации (2D проекция), не для препроцессинга перед кластеризацией.

- Поиск гиперпараметров:
  - KMeans: перебор k в диапазоне от 2 до 20, фиксированы `random_state=42` и `n_init=10`. Выбор оптимального k основан на максимизации silhouette score.
  - DBSCAN: построение k-distance графика для подбора eps (min_samples=5), перебор eps в диапазоне [0.3, 0.5, 0.7, 1.0, 1.5, 2.0, 2.5, 3.0] в зависимости от датасета, перебор min_samples в [3, 5, 7]. Выбор лучших параметров: максимизация silhouette score при условии, что доля шума < 30-40%.
  - AgglomerativeClustering: перебор k в диапазоне от 2 до 10, тестирование linkage ['ward', 'complete', 'average']. Выбор лучших параметров: максимизация silhouette score.

- Метрики: `silhouette_score` (выше - лучше, диапазон [-1, 1]), `davies_bouldin_score` (ниже - лучше), `calinski_harabasz_score` (выше - лучше). Для DBSCAN: метрики считаются только на non-noise точках (label != -1), так как шумовые точки не принадлежат кластерам. Доля шума явно фиксируется.

- Визуализация: PCA(2D) для всех датасетов с фиксированным `random_state=42`. PCA применяется к масштабированным данным для визуализации результатов кластеризации. t-SNE не использовался (опционально).

## 5. Analysis

### 5.1 Сравнение алгоритмов (важные наблюдения)

- **Где KMeans "ломается" и почему?**
  - На датасете 02: KMeans плохо работает из-за нелинейной структуры кластеров. Алгоритм предполагает сферические кластеры, а данные имеют более сложную форму.
  - На датасете 03: KMeans может плохо обрабатывать кластеры разной плотности, так как предполагает кластеры одинакового размера.

- **Где DBSCAN/иерархическая кластеризация выигрывают и почему?**
  - DBSCAN на датасете 02: выигрывает благодаря способности находить кластеры произвольной формы и выделять выбросы как шум. Это критично для нелинейных структур.
  - AgglomerativeClustering на датасете 03: выигрывает благодаря способности работать с кластерами разной плотности через иерархическое объединение. Разные типы linkage (ward, complete, average) по-разному обрабатывают расстояния между кластерами.

- **Что сильнее всего влияло на результат?**
  - **Масштабирование**: критично для всех distance-based методов. Без масштабирования на датасете 01 результаты были бы полностью искажены.
  - **Выбросы**: на датасете 02 выбросы мешали KMeans, но DBSCAN успешно их обрабатывал как шум.
  - **Плотность кластеров**: на датасете 03 разная плотность кластеров требовала иерархического подхода.
  - **Структура данных**: линейная vs нелинейная структура определяла выбор между KMeans и DBSCAN.

### 5.2 Устойчивость (обязательно для одного датасета)

- Какую проверку устойчивости делали: Проверка устойчивости KMeans на датасете 03. Выполнено 5 запусков с разными `random_state` (42, 123, 456, 789, 999) при фиксированном оптимальном k. Вычислен Adjusted Rand Index (ARI) между всеми парами запусков для оценки согласованности разбиений.

- Что получилось: Средний ARI между парами запусков: 1.0000. Стандартное отклонение ARI: 0.0000. Минимальный/максимальный ARI: 1.0000 / 1.0000. Средний ARI = 1.0 указывает на полную идентичность всех разбиений между запусками, что говорит о высокой устойчивости.

- Вывод: KMeans показал устойчивые результаты на датасете 03. Это связано с хорошо разделимыми кластерами - при оптимальном k=3 все запуски с разными random_state дают идентичное разбиение, что указывает на чёткую структуру данных и стабильность алгоритма.

## 6. Conclusion

4-8 коротких тезисов: чему научились про кластеризацию, метрики и корректный протокол unsupervised-эксперимента.

1. **Препроцессинг критичен**: Масштабирование признаков обязательно для distance-based методов. Без масштабирования результаты полностью искажаются из-за разных шкал признаков.

2. **Выбор алгоритма зависит от структуры данных**: KMeans хорош для сферических кластеров, DBSCAN - для нелинейных структур и выбросов, AgglomerativeClustering - для кластеров разной плотности.

3. **Комбинация метрик важна**: Использование нескольких внутренних метрик (silhouette, Davies-Bouldin, Calinski-Harabasz) позволяет более объективно оценить качество кластеризации, так как каждая метрика имеет свои ограничения.

4. **Особенности DBSCAN**: При работе с DBSCAN важно корректно обрабатывать шумовые точки - метрики считаются только на non-noise точках, а доля шума явно фиксируется и интерпретируется.

5. **Подбор параметров требует анализа**: k-distance график для DBSCAN и графики метрик для KMeans помогают выбрать разумные параметры, но окончательный выбор должен учитывать несколько критериев.

6. **Визуализация помогает, но ограничена**: PCA(2D) теряет информацию при проекции, но остаётся полезным инструментом для понимания структуры данных и результатов кластеризации.

7. **Проверка устойчивости важна**: Для методов с случайной инициализацией (KMeans) проверка устойчивости через ARI между запусками помогает оценить надёжность результатов.

8. **"Честный" протокол**: В unsupervised-эксперименте важно фиксировать все параметры (random_state), использовать относительные пути, сохранять артефакты и документировать процесс для воспроизводимости.
